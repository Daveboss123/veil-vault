# Supplied-record sample

**Fabricated demonstration file. This is not chain evidence.**

`supplied-records-SAMPLE.json` exercises the supplied-record checker without a
wallet, network connection or live round. It contains:

- an official Zcash testnet Sapling test-vector address, which controls no funds;
- a fixed four-runner round with two Crown claims, one Moon claim and one Copper
  claim;
- deterministic, fabricated transaction IDs;
- fixed sample tags and secrets so the file can be regenerated byte for byte.

No transaction was signed, sent or mined for this file. Do not describe it as a
live testnet result, and do not publish it as a transaction receipt.

## Expected result

- Four accepted commitments and four accepted reveals.
- The two Crown claims collide, so the Crown scores zero.
- The Moon runner (`00b14f39ac806af0`) wins with 5 relics.
- The Copper runner scores 3.
- No records are rejected.

## Check it offline

```powershell
npm.cmd run audit -- docs/examples/supplied-records-SAMPLE.json
npm.cmd run audit -- docs/examples/supplied-records-SAMPLE.json 00b14f39ac806af0
```

The second command also requires the announced winner tag to match. Replace it
with `none` to require that no runner wins.

## Check it in the browser

Open the Testnet Lab, find **Supplied-record checker**, and import
`supplied-records-SAMPLE.json`. The file is read locally and is not uploaded.

## Regenerate it

```powershell
npm.cmd run sample:audit
```

The generator is `scripts/make-sample-audit.ts`. It is deterministic and exists
only to keep the sample and its regression test in sync.

## Why the secrets are visible

A valid reveal necessarily discloses the one-round runner tag, chosen vault and
random secret. The sample includes fabricated values so the checker can verify
the commitment chain. A real receipt must stay private until its reveal is
intentionally sent. The sample's tags and secrets belong to no person and no
wallet.

## Limits

Passing the checker means the supplied file is internally consistent with the
protocol. It does not prove that the file is complete, that the transaction IDs
exist, or that the transactions were mined. Independent chain retrieval is a
separate, stronger claim.
